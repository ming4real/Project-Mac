2. Bus identification and confirmed probe blocker

   Live ACPI exposes BCM2E7C:00 at \_SB_.PCI0.URT0.BLTH, status 15,
   with alias acpi:BCM2E7C:APPLE-UART-BLTH:. URT0 is Intel PCI function
   0000:00:1e.0 (8086:a127). Its intel-lpss driver instantiated the
   platform device dw-apb-uart.2, which was unbound with
   waiting_for_supplier=0. There was no /sys/bus/serial. The UART was
   runtime-suspended, an observation before driver binding that does
   not establish an electrical power fault.

   The SHA-256 of the MacBook's /boot/bzImage matches dingle's baseline
   deploy image (a7c80d7ec29718de65054c8f3aa6108df35bfd338c835f6fd71179c17e1fe7a6).
   The matching build config has BT and BT_HCIBTUSB as modules and
   BT_LE enabled. SERIAL_8250_DW, SERIAL_DEV_BUS and BT_HCIUART are
   unset. Linux therefore cannot enumerate and bind this UART child
   as an HCI device. The USB-driver test targeted a different transport.
   BlueZ is needed for userspace operation and cannot remedy this
   missing kernel device. Optional BCM43602 Wi-Fi files are unrelated
   to the missing Bluetooth UART probe.

   The exact 6.18.63 sources on dingle contain BCM2E7C in
   drivers/bluetooth/hci_bcm.c. The driver handles Apple's BTLP, BTPU
   and BTPD ACPI methods and the baud property. drivers/tty/serdev/core.c
   matches Apple UART children using that property when the resource
   template is empty. The controller's actual HCI response, chip
   revision and patch-RAM requirements remain to be measured after
   driver binding. No hardware fault was demonstrated.

3. Candidate changes and build

   recipes-kernel/linux/files/macbook-display.cfg enables DesignWare
   8250 and HCI UART as modules, serdev and its TTY controller in the
   kernel, and the Broadcom HCI UART protocol. The 8250 runtime slot
   count grows from four to eight to give LPSS UARTs room after the
   legacy slots while preserving the configured ttyS0 console.
   Existing USB Bluetooth support is retained. The first configure
   pass dropped BT_HCIUART_BCM because the baseline disabled GPIOLIB.
   Enabled GPIOLIB, a Kconfig dependency, and restarted the build.

   layers/project/meta-mac-distro/recipes-images/images/mac-image.bb
   installs bluez5 for macbookpro14-3. The pinned OE-Core recipe enables
   the client, tools and systemd integration by default. No speculative
   firmware or downstream driver patch was added. The image already
   installs linux-firmware and the iBridge, Touch Bar and ALS packages.

   Built on dingle under build/ble using the project's kas entry point
   and separate build and output directories. The first attempt logged
   BitBake basehash mismatches on image tasks and was interrupted for
   the GPIOLIB correction. The retry completed all 11,635 tasks without
   those errors. The candidate .config retained BT_HCIUART_BCM and all
   requested UART settings. The rootfs contains BlueZ 5.86-r0,
   bluetoothctl, btmon, bluetoothd and bluetooth.service. The module
   index maps platform:dw-apb-uart to 8250_dw and acpi*:BCM2E7C:* to
   hci_uart. The manifest includes the existing brcmfmac and all three
   iBridge packages.
